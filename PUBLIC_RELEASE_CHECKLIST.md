# Public Release Checklist

Use this checklist before changing the repository visibility to public.

## Required before publishing

- [ ] Confirm no real decision journal entries are committed.
- [ ] Confirm `entries/` contains only fictional examples or is empty.
- [ ] Confirm no employer, customer, vendor, colleague, partner, family, or personal information is included.
- [ ] Confirm no private financial, health, relationship, immigration, legal, HR, career, or negotiation details are committed.
- [ ] Confirm no API keys, tokens, credentials, connector details, account identifiers, private paths, or emails are present.
- [ ] Confirm examples are clearly fictional.
- [ ] Confirm the README does not imply decision-quality certification, psychological advice, financial advice, legal advice, or employment advice.
- [ ] Confirm the license, README, and quick-start commands are accurate.

## Recommended before promotion

- [ ] Add one fictional full lifecycle example from decision capture to review.
- [ ] Add tests for entry parsing and due-date workflows.
- [ ] Add a `review` command before making stronger decision-quality claims.
- [ ] Run tests locally after a fresh clone.

## Final manual review

Before publishing, search the repo for real names, company names, relationship details, personal notes, emails, tokens, private paths, and real decision entries.

This checklist is a publication aid, not a privacy or security guarantee.
